# 技术文档问答助手 · 需求文档

> 版本：v1.0
> 项目类型：个人作品 / AI 应用交付能力证明
> 目标读者：自己（开发）、未来面试官（架构与决策说明）
> 技术基线：Vue3 + Vite + TypeScript + Pinia + FastAPI + OpenAI 兼容接口

---

## 1. 项目概述

### 1.1 背景

做一个面向"技术文档"的 AI 问答助手：用户上传或指定技术文档后，可以基于文档内容提问，获得带引用来源的回答。项目分阶段交付，第一阶段先完成一个稳定、可演示的 AI 聊天壳，验证流式交互、错误处理与工程闭环；第二阶段接入 RAG；第三阶段加入工具调用雏形。

### 1.2 项目目标

- 掌握 AI 应用前端的核心交互：流式输出、中断、重试、Markdown 渲染、引用展示。
- 形成一个可部署、可演示、可讲清楚架构决策的完整项目。
- 作为求职作品，证明"前端 + AI 应用交付"能力，而非单纯页面还原。

### 1.3 成功标准

- 第一阶段项目可独立部署上线，陌生用户能完成一次完整对话。
- 能闭卷讲清楚流式解析、AbortController、消息状态机、前后端接口契约。
- GitHub README 包含架构图、关键决策、踩坑记录。
- 第二阶段完成后，回答能展示引用来源，检索为空时有降级 UI。

## 2. 用户与使用场景

### 2.1 目标用户

- 需要快速查阅技术文档的开发者（主要演示对象）。
- 面试官 / 作品评审者（通过演示理解工程能力）。

### 2.2 核心场景

1. 用户打开页面，输入技术问题，获得逐字流式回答。
2. 用户中途点击"停止生成"，请求被真正中断，界面状态正确收尾。
3. 请求失败或限流时，用户看到可重试提示，点击重试后恢复。
4. （P1）用户上传技术文档，提问后回答下方展示引用片段与来源。
5. （P2）用户让助手调用一个工具（如查询天气/查询内部数据），前端展示工具调用中间状态，敏感操作需用户确认。

## 3. 范围与优先级

### 3.1 P0：第一阶段 MVP（聊天壳）

- 单页面聊天界面
- 流式对话（SSE / ReadableStream）
- 停止生成（AbortController）
- 多轮上下文
- Markdown 渲染 + 代码高亮 + 代码块复制
- 错误态与重试
- API Key 仅存后端
- 可部署演示

### 3.2 P1：第二阶段（RAG 文档问答）

- 文档上传与解析（Markdown/PDF/纯文本）
- 文档切块、向量化、检索
- 回答附带引用来源卡片
- 检索为空/低置信度降级 UI
- 引用点击定位原文片段

### 3.3 P2：第三阶段（Agent 雏形）

- Function Calling 工具调用
- 工具调用中间状态展示
- 敏感操作用户确认（Human-in-the-loop）
- 工具失败的回滚/重试 UI

### 3.4 非目标（明确不做）

- 不训练/微调模型
- 不做多租户、复杂权限体系
- 不做完整知识库管理后台（增删改查、版本管理暂不做）
- 不做移动端原生 App
- 不做支付、商业化功能

## 4. 功能需求

### 4.1 会话管理（P0）

- 支持新建会话、切换会话、删除会话（可先本地存储）。
- 每个会话保存消息列表与上下文。
- 刷新页面后会话可恢复（localStorage / IndexedDB 均可，MVP 用 localStorage）。

### 4.2 流式对话（P0）

- 用户输入问题，点击发送后，助手消息以流式逐字显示。
- 前端维护 buffer，正确处理 `data:` 行、`[DONE]`、半截 chunk。
- 流式过程中输入框可禁用或允许排队（MVP 建议禁用发送，允许停止）。
- 首 token 到达时间目标 < 3 秒（依赖上游模型，需在 README 说明）。

### 4.3 停止生成（P0）

- 流式过程中显示"停止生成"按钮。
- 点击后通过 AbortController 中断请求。
- 中断后消息状态置为 done 或 stopped，保留已生成内容，不报错。
- 后端需处理客户端断开，避免资源泄漏。

### 4.4 重试与错误处理（P0）

- 请求失败、超时、限流、后端 5xx 时，展示可读错误提示。
- 错误消息旁提供"重试"按钮。
- 重试策略：MVP 采用原地重发或新建助手消息，需在实现中明确一种并写入 README。
- 区分错误类型：网络错误、上游限流、鉴权失败、格式错误。

### 4.5 Markdown 渲染（P0）

- 助手消息支持 Markdown 渲染。
- 代码块语法高亮，提供复制按钮。
- 流式过程中增量渲染不能导致页面闪烁或代码块反复重排（可节流渲染）。

### 4.6 多轮上下文（P0）

- 前端维护 messages 数组（role/content），每次请求携带上下文。
- 需设定上下文长度上限策略（如保留最近 N 轮或按 token 截断），MVP 可先保留最近 10 轮并在 README 说明。

### 4.7 文档上传与问答（P1）

- 支持上传 Markdown/PDF/纯文本。
- 上传后展示文档列表与处理状态（解析中/就绪/失败）。
- 提问时先检索相关片段，再基于片段生成回答。
- 回答下方展示引用来源：文档名 + 片段摘要，点击可定位原文。

### 4.8 引用与降级（P1）

- 每条引用可展开查看原文片段。
- 检索结果为空或置信度低于阈值时，展示降级提示："未找到相关依据，以下为一般性回答"，并允许用户重新提问。

### 4.9 工具调用（P2）

- 支持至少一个工具（如查询天气 API 或查询本地 JSON 数据）。
- 前端展示"正在调用工具…"中间状态。
- 敏感操作弹出确认框，用户可确认或拒绝。
- 工具失败时展示失败原因与重试入口。

## 5. 页面与交互

### 5.1 页面结构（MVP 单页）

- 左侧：会话列表（新建、切换、删除）
- 中间：消息流区域（用户消息、助手消息、错误提示、引用卡片）
- 底部：输入框 + 发送按钮 + 停止按钮
- 顶部：项目名称、模型标识、清空会话入口

### 5.2 消息状态机

每条助手消息状态：

- `idle`：尚未请求
- `streaming`：流式生成中
- `done`：正常完成
- `stopped`：用户中断
- `error`：失败，可重试

UI 必须根据状态渲染不同操作按钮（停止/重试/复制）。

### 5.3 关键交互

- 发送后自动滚动到底部；用户向上滚动时暂停自动滚动。
- 停止后保留已生成内容。
- 错误提示不覆盖历史消息。
- 引用卡片默认折叠，点击展开。

## 6. 技术架构

### 6.1 前端

- Vue3 + Vite + TypeScript
- Pinia 管理会话与消息状态
- UI 库：Naive UI 或 Element Plus（二选一）
- Markdown：markdown-it + highlight.js
- 流式请求：fetch + ReadableStream + TextDecoder
- 中断：AbortController

### 6.2 后端

- Python + FastAPI + httpx
- 提供 `/api/chat` 流式转发接口
- 环境变量管理 API Key，前端不接触密钥
- P1 增加文档解析、切块、向量检索接口
- P2 增加工具调用编排接口

### 6.3 数据与存储

- MVP：会话存 localStorage；后端无数据库
- P1：向量库可用 Chroma/Qdrant（本地或轻量云）
- 文档元数据可先用本地文件/SQLite

### 6.4 部署

- 前端：Vercel/Netlify
- 后端：Render/Railway/Fly.io 或本地演示 + 录屏
- README 必须写清楚部署步骤与环境变量

## 7. 接口契约（MVP）

### 7.1 POST /api/chat（流式）

请求体

```json
{
  "messages": [
    { "role": "user", "content": "什么是闭包？" }
  ]
}
```

响应：`text/event-stream`

```text
data: {"choices":[{"delta":{"content":"闭"}}]}
data: {"choices":[{"delta":{"content":"包"}}]}
data: [DONE]
```

错误响应

```json
{ "error": { "code": "RATE_LIMITED", "message": "请求过于频繁，请稍后重试" } }
```

### 7.2 GET /api/health

返回 `{ "status": "ok" }`，用于部署健康检查。

### 7.3 P1 预留接口

- `POST /api/documents`：上传文档
- `GET /api/documents`：文档列表与状态
- `POST /api/chat` 请求体增加 `useRag: true`

## 8. 数据模型（前端）

```ts
type MessageRole = 'user' | 'assistant' | 'system'

interface Message {
  id: string
  role: MessageRole
  content: string
  status: 'idle' | 'streaming' | 'done' | 'stopped' | 'error'
  error?: { code: string; message: string }
  citations?: Citation[] // P1
}

interface Citation {
  docId: string
  docName: string
  snippet: string
  score?: number
}

interface Conversation {
  id: string
  title: string
  messages: Message[]
  createdAt: number
  updatedAt: number
}
```

## 9. 非功能需求

### 9.1 安全

- API Key 仅存后端环境变量，前端请求只打自己的后端。
- 不提交 .env 到 Git。
- 后端对请求体做基本校验，限制消息长度与频率（MVP 可简单限流）。

### 9.2 性能

- 首 token 目标 < 3 秒（受上游影响，需在 README 标注实测）。
- 流式渲染节流，避免每个字符触发整页重渲染。
- 会话列表与消息列表在 100 条消息内保持流畅。

### 9.3 可观测性

- 后端记录请求开始/结束、错误码、上游状态。
- 前端错误上报可先 console + 页面提示，MVP 不接监控平台。

### 9.4 代码质量

- TypeScript 严格模式。
- 核心流式解析、状态机、AbortController 必须手写并附注释。
- README 包含架构图、关键决策、踩坑记录。

## 12. 风险与开放问题

- 上游模型限流/费用：选择低价或免费额度模型，后端做简单限流；README 说明成本控制。
- 流式解析边界：最后一个 chunk 可能不完整，必须保留 buffer，不能假设每次 read 都是完整行。
- 渲染性能：流式 Markdown 渲染可能抖动，需节流或分段渲染。
- RAG 幻觉引用：P1 必须让引用来自检索片段，低置信度走降级 UI。
- 部署后端休眠：免费后端可能冷启动，演示前预热或本地录屏兜底。
